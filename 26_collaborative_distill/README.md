# 26 协作蒸馏（"大教授 brainstorm" → 单模型）

> 主线：老师重新定义了蒸馏目标——不再"压缩模型"，而是把"多智能体协作产生的群体智能"高效搬进单个模型。
> 老师原话（三句拆解见 上下文交接.md）：
> 1. "一杯浑水，就算有有机物，不停搅，能撞出单细胞生物吗？" → 别指望"投票/并集"这种机械叠加搅出智能（已证：简单融合 NO-GO，-0.50pp）。
> 2. "我只见过几个大教授/成功人士 brainstorm 一下就有机会出好 idea" → 真正的机制是"少而强、有质量地互相 challenge"。
> 3. "LoRA 已经够用" → 训练/搬运动作不是瓶颈，LoRA 就够；瓶颈在"好答案从哪来"。

---

## 一、实验目标

把"3 个最强模型的群体智能（并集/协作上限）"通过"教授辩论"机制产生一个比任何单模型都准的"协作答案"，再把这个协作答案用 LoRA 蒸馏进单个学生，让学生**超越任何一个单个老师**。

一句话：**不是搅浑水（投票），而是让三个大教授坐下来辩论，把辩论出的好答案搬进学生。**

---

## 二、老师选谁（核心决策）+ 预判为什么

### 选这 3 个（"三大教授"，全部 ~90% SOTA 推理模型）

| 教授 | API model id | 测试集零样本 | 厂商 |
|---|---|---|---|
| DeepSeek-V4-Pro | `deepseek-v4-pro-260425` | 90.33% | DeepSeek |
| GLM-5.2 | `glm-5-2-260617` | 90.54% | 智谱 Zhipu |
| 豆包 seed-2.1-turbo | `doubao-seed-2-1-turbo-260628` | 90.82% | 字节 ByteDance |

- 三个统一走 ark 端点 `https://ark.cn-beijing.volces.com/api/v3/chat/completions`，同一个 key（`DOUBAO_API_KEY`，已配，冒烟测试 smoke_glm_and_dsv4pro.py / compare_doubao_turbo.py 已通过）。
- 明确**不选**的三类：flash（deepseek-chat 79.8%，是"中等生"不是"教授"）、Qwen3-32B（74%，要当学生）、Llama-70B（86.82% 是训练集污染虚高，测试集只有 72.43%，不可信）。

### 预判：为什么是这 3 个（先写下来，再验证）

**理由 1 —— 强度匹配"大教授"比喻（字面意思）。**
老师说的是"几个大教授/成功人士 brainstorm"，不是"一屋子中等生投票"。之前拿 flash(80%)+llama70b(86%污染)+qwen3(74%) 搅在一起做融合，本质是"中等生投票"，所以抓不住互补（-0.50pp）。三大教授才是场里最强的三个人。

**理由 2 —— 跨厂商 = 跨训练语料/架构 → 错误互补。**
DeepSeek / 智谱 / 字节 三家独立，预训练语料、SFT 偏好、推理范式都不同。已有硬证据：flash 做错的题里，qwen3 也错 66.8%（33% 互补）、llama70b 只错 39.4%（60% 互补）——"不同厂商模型错误不重叠"真实存在。预测三强的错误重叠率比三弱更低。

**理由 3 —— "少而强"的分歧面窄，辩论信号集中（这是关键）。**
三个 ~90% 的模型在绝大多数题上意见一致（全对），只有约 5~10% 的题有分歧。brainstorm 只需在这 5~10% 的分歧题上"辩论"，成本低、命中率高；而且强模型被 challenge 时给的理由有分量，错的一方更可能被说服——这正是"brainstorm 能出好 idea"、而"搅水"不能的机制差异。反之三弱错误多、分歧面宽，辩论面太宽、噪声太大，谁也不能说服谁。

**理由 4 —— 工程可行（快速启动）。**
同一端点同一 key；三个模型冒烟测试已过；已有部分测试集标签（dsv4pro 有 medqa 1228 + mmlu 1679 题），可先低成本验证互补性再决定全量。

### 四条可证伪的预测（Phase 0 用测试集先验证）

- **P1（并集上限）**：三强并集准确率 > 95%，高于三弱（flash/llama/qwen3）的 93.66%。
- **P2（错误重叠）**：三强两两错误重叠率 < 50%（三弱里 flash 错时 qwen3 也错 66.8%）。
- **P3（辩论抓互补）**：辩论/仲裁产出的"协作答案" > 简单多数投票（投票=搅水，历史 -0.50pp），即辩论能实现并集上限的相当一部分。
- **P4（主判据）**：协作答案蒸馏进 Qwen3-32B 后，学生超越最强单教授（~90.8%），实现"群体智能 → 单模型"。

**反向预测（诚实边界，同样先写）**：
- R1：若三强过于一致（错误重叠极高、并集增益 <1pp），则"大教授之间没什么可 brainstorm 的"，需换"互补型"教授（如引入一个不同训练分布的中等强模型）。—— Phase 0 一算就知道。
- R2：若辩论抓不住互补（分歧题上理由质量不足以判对错，协作答案 ≈ 投票 ≈ 单教授），则得到诚实的负面结果，支撑"群体智能迁移需要更强机制"这个结论本身。

## 三、协作机制："教授辩论"（不是投票）

三阶段，核心是 R2 的"互相 challenge"：

- **R1 独立作答**：3 教授各自独立对每题输出【答案字母 + 一句理由】。temperature=0，max_tokens 放大到 ~1024 拿理由（复用 `shared/generate_teacher_cot.py` 的思路，改英文 prompt）。
- **R2 交叉辩论（brainstorm 的核心）**：把三份【答案+理由】打包发给每个教授，请它"看别人理由，被说服就改、否则坚持，输出【最终答案 + 置信度 0~1 + 一句反驳理由】"。这一步是"互相 challenge"，区别于数票。
- **R3 收敛**（三个变体，做对比）：
  - 变体 A「主席仲裁」：最强教授（豆包 90.82%）当主席，读 R2 三份最终答案+理由后拍板。
  - 变体 B「置信度加权投票」：R2 三份【答案,置信度】加权取最大。
  - 变体 C（对照）「简单多数投票」：R1 三份答案纯数票 = 历史"搅水"，本轮重做同口径当 baseline。

产出 = 每道题的**协作答案**（CollaborativeAnswer）。

> 关键机制解释（大白话）：投票之所以抓不住互补，是因为"无法判断哪个老师在某题是对的"。辩论用"理由"提供了这个判断信号——分歧题上，错的一方理由被挑战时更容易露馅、更容易被说服改口。所以协作答案预期比"数票"更接近并集上限。

## 四、蒸馏进学生（LoRA，复用现成）

- **学生 = Qwen3-32B**（本地最强，零样本 73.84%）。理由：承接 90%+ 协作标签需要够强的学生；它在中文牙科已验证 +4.8pp 增益，是当前最优学生。
- **标签 = 协作答案**（替换原来的 GT/单教师标签），跑 `shared/train_choice_head_distill.py`。
  - 首选 α=0（纯协作答案监督，与"不参考老师软标签"的历史结论一致）。
  - 可选 α=0.5（用协作答案的软分布做软标签）做消融。
- **LoRA rank16 / alpha32**（"LoRA 够用"，老师已拍板，不再折腾 rank64/128）。
- 训练量：全量 20488 题，1 epoch；只在"协作答案"与标准答案一致的题上练（去掉协作答案自己都错的题，避免把错误标签教给学生）。

## 六、成功判据（怎么算赢）

- **主判据**：协作答案蒸馏后的学生 > 最强单教授（~90.8%）。这才是"群体智能搬进单模型、学生超越任何单个老师"。
- **副判据 1**：协作答案准确率 > 任何单教授（证明"brainstorm 抓到了互补"）。
- **副判据 2**：协作答案 > 多数投票 B1（证明"辩论优于搅水"）。
- 口径：全量 8293 题（medqa 1273 + medmcqa 4183 + mmlu 2837）。

## 七、执行步骤（分阶段，先便宜验证再全量）

- **Phase 0（便宜，验证 P1/P2/R1，决定要不要继续）**：
  给 3 教授在测试集 8293 题上补全标签（现 dsv4pro 只有 medqa 1228 + mmlu 1679，glm52/doubao 只有几百题），算三强并集 + 两两错误重叠。若 P1/P2 成立（有互补可抓）→ 继续；若 R1 成立（并集增益 <1pp）→ 换教授方案，不浪费全量成本。
- **Phase 1（训练集 R1）**：3 教授 × 20486 题独立作答+理由。成本大，先跑 6000 题子集验证机制有效，再全量。
- **Phase 2（辩论 R2+R3）**：只在分歧题上做交叉辩论 + 三种收敛变体，产出协作答案。
- **Phase 3（蒸馏）**：协作答案 → Qwen3-32B（LoRA，α=0）。
- **Phase 4（评估）**：8293 题全量，主/副判据 + 3 条基线，落盘 JSON + md。

粗成本估算（供决策）：R1 全量 ≈ 61458 次 API 调用；分歧题假设 8% ≈ 1600 题 × 3 教授 R2 ≈ 4800 次；测试集 8293 × 3 ≈ 24879 次；合计 ~9 万次调用，数小时级（可并发 + 断点续跑）。**先 Phase 0 + 6000 子集，用几百次调用就能验证机制，再决定是否全量。**

## 九、关键坑（沿用既有结论）

- Qwen3 学生必须 `DISTILL_USE_CHAT_TEMPLATE=1` + 关 thinking。
- α=0 时训练数据只需 Question/Options/Answer（这里 Answer=协作答案），无需教师软标签。
- 正确率以全量 8293 题口径为准；不要用训练集口径（Llama 污染教训）。
- API 调 3 教授统一走 ark + DOUBAO_API_KEY；reasoning 模型 max_tokens 要放大（dsv4pro 历史踩过 max_tokens 截断的坑，见 smoke_dsv4pro_maxlen.py）。
