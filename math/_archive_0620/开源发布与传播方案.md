# 开源发布与传播方案（为"不会做广告"的人设计）

> 日期：2026-06-20
> 痛点：用户不擅长主动宣传，但希望工具被人发现并使用。
> 解法：靠"好文档 + 标准化做法 + 让工具长在别人会搜到的地方"，把传播变成被动发生，而非主动吆喝。
> 同时准备合理的开源许可证。

---

## 0. 核心思路：让别人"搜得到、看得懂、跑得通、信得过"

不会做广告没关系——开源工具的传播 90% 靠这四件事，全是一次性投入的"软件工程"，不是持续吆喝：
1. **搜得到**：出现在别人会搜索的地方（关键词、平台、论文链接）。
2. **看得懂**：README 30 秒讲清"解决什么问题、凭什么可信"。
3. **跑得通**：5 分钟能复现一个结果（降低试用门槛）。
4. **信得过**：有论文、有外部验证、有许可证（让人敢用、敢引）。

---

## 1. 许可证选择（现在就能定）

| 许可证 | 特点 | 适合你吗 |
|---|---|---|
| **MIT** | 最宽松，任何人可商用/修改，只需保留版权声明 | ✅ **推荐**：学术工具求采用率，越宽松越多人用 |
| Apache-2.0 | 类似 MIT，额外含专利授权条款 | ✅ 可选：若担心专利纠纷，比 MIT 更稳 |
| GPL-3.0 | 传染性，衍生作品也须开源 | ❌ 不推荐：会吓退商业用户，降低采用 |
| CC-BY-4.0 | 用于数据/文档，要求署名 | 数据集/文档部分可用 |

**建议**：代码用 **MIT**（最大化采用），论文/文档用 **CC-BY-4.0**（要求署名=保护你的学术信誉）。
- 注意：CMExam 等第三方数据有自己的许可，仓库里要单独声明"数据遵循原始许可，本仓库许可仅覆盖代码"。

## 2. 文档体系（让人"看得懂、跑得通"）

独立仓库需要的文档（按重要性）：

### 2.1 README.md（门面，决定 80% 的去留）
必含，且前 10 行最关键：
- 一句话：这工具解决什么问题（"训练前给蒸馏教师做体检，找出它不可信的知识区"）。
- 一张图/一个例子：体检报告长什么样（贴 GLM 报告片段）。
- 凭什么可信：一行点出"不可信区对应人类专家难度，跨6+模型验证"（+论文链接）。
- 30秒安装 + 5分钟跑通的命令。
- 徽章：license、python版本、论文 arXiv 链接。

### 2.2 完整文档（已有基础，搬到新仓库）
- `复现指南.md` → reproduce.md（建议出英文版，扩大受众）。
- `实验脚本索引.md` → 工具/脚本说明。
- `工具独立验证方案.md` → 让人知道如何参与验证。

### 2.3 贡献与验证指南 CONTRIBUTING.md（关键，把用户变验证者）
- 教别人"如何用自己的模型/数据跑体检并回传匿名验证结果"。
- 这是把"邀请测试"标准化——别人按文档就能参与，你不用一对一邀请。

### 2.4 示例 examples/（降低试用门槛）
- 一个 `quickstart.ipynb` 或 `demo.sh`：用小模型(Qwen2.5-7B)+小数据，5分钟出体检报告。
- 人能跑通一次，就会信、会留。

## 3. "搜得到"的被动渠道（一次性投入，无需持续吆喝）

| 渠道 | 怎么做 | 为什么被动有效 |
|---|---|---|
| **论文 + arXiv** | 发论文，仓库链接放论文里 | 搜该领域的人会顺着论文找到工具 |
| **Papers with Code** | 提交"论文↔代码"关联 | 该领域研究者的标准检索入口 |
| **GitHub Topics/关键词** | 仓库打标签：knowledge-distillation, model-evaluation, llm-uncertainty | 别人按 topic 浏览能撞见 |
| **Hugging Face** | 把体检报告/工具做成 HF Space 或 dataset card | LLM 社区聚集地，自带流量 |
| **README 的 SEO** | 标题/描述含别人会搜的词（"teacher selection distillation", "training-free"） | Google/GitHub 搜索命中 |
| **一篇技术博客** | 写一篇讲"发现"的博客（不是广告，是分享发现） | 一次写成，长期被搜到/被转 |

> 关键认知：这些都是**一次性设置**，设好后是"别人来搜到你"，不是"你去推销"。完全适合不爱宣传的人。

---

## 4. "信得过"的信号（让人敢用敢引）

- ✅ 论文（同行评议背书）
- ✅ 外部验证结果（留出模型 + 多数据集 + 未来他人验证）
- ✅ 许可证（敢商用）
- ✅ 可复现（一键跑通）
- ✅ 诚实的 limitations 章节（反而增加可信度——严谨的人会因为你诚实而信任你）

## 5. 执行清单（独立仓库就绪时一次性做）

- [ ] 选 LICENSE：代码 MIT + 文档 CC-BY-4.0 + 数据许可单独声明
- [ ] 写 README.md（英文，前10行讲清问题+可信度+快速开始）
- [ ] 搬迁并翻译核心文档（reproduce / scripts / 验证方案）
- [ ] 写 CONTRIBUTING.md（把"邀请测试"变成标准流程）
- [ ] 做 examples/quickstart（5分钟跑通）
- [ ] 提交 Papers with Code、打 GitHub topics、（可选）HF Space
- [ ] 论文里放仓库链接，仓库里放论文链接（双向）
- [ ] 写一篇技术博客讲"发现"（可选，但性价比高）

---

## 6. 一句话

**你不需要会做广告——你需要把工具做成"别人搜得到、看得懂、跑得通、信得过"的样子。**
这四件事是一次性的工程投入，做好后传播会被动发生。
其中最强的传播载体是**论文本身**：好的科学发现 + 可复现工具 + 诚实验证，会让同行主动找上门。
时机：等研究闭环、独立仓库迁移时一次性落实（现在不急，先把科学结论做扎实）。
