# 两个新方向：跨国模型融合复活 + 学生容量下限预测

> 日期：2026-06-20
> 用户两个关键修正/新问题：
> (1) "全能强者"结论下早了——没测国外主流模型 + 英文题。Qwen32B 做英文未必最强。
> (2) 新问题：学生模型选小一点若能学会教师，也有价值。如何预测"保证正确率前提下，学生模型的下限（最小容量）"？这有经济价值。
> 本文评估这两个方向，给验证方案与诚实难点。

---

## 方向一：融合蒸馏可能"复活"（撤回过早的否决）

### 1.1 我之前的错误
5e 否决融合，依据是"Qwen32B 在全部7学科都最强"。但这只在**中文 CMExam + 6个偏中文模型**的阵容里成立。**结论下早了。**

### 1.2 数据已露头：英文上优势消失
E2 英文数据集（已有真实数据）：
| 数据集 | Qwen32B | Phi4(微软) | 差距 |
|---|---|---|---|
| CMExam(中) | 89.4% | 54.5% | **34.9pp** |
| MedQA(英) | 71.7% | 70.9% | **0.8pp** |
| MMLU-full(英) | 80.6% | 78.6% | 2.0pp |
| MMLU-med(英) | 88.4% | 87.9% | 0.5pp |

→ Qwen 的"碾压"是**中文医学的局部现象**。英文上 Phi-4 几乎追平。
→ **引入国外主流模型（GPT/Claude/Llama/Mistral/Gemini）+ 英文题，极可能出现真正的领域互补**，融合就有空间。

### 1.3 修正后的结论
- 融合**不是被否决**，而是"**在当前中文偏向阵容里无效**"。
- 待验证假设 H5：**在跨语言/跨来源的异质教师阵容里，不存在全能教师，领域路由融合 oracle 上界 > 0 且可观。**

### 1.4 验证方案
1. **扩教师阵容**：加国外主流模型。本地有 Llama-3.3-70B（已有！）。需补 Mistral、Gemma 系列已有。
   - API 模型（GPT/Claude）：若有 key 可加，但注意成本与可复现性（论文倾向用开源可复现模型）。
2. **多语言数据集**：CMExam(中) + MedQA/MMLU(英) 都已有。
3. **重跑 fusion_upper_bound**：在"中英混合 + 国内外混合教师"上看领域路由 oracle 上界。
4. 若上界可观 → 融合方向复活，做完整融合蒸馏。

### 1.5 诚实边界
- 即使英文上互补，"领域级"路由可能仍太粗（5e 教训：组内最强可能还是同一个）。需同时看"样本级 oracle 上界"。
- API 模型不可复现、成本高，论文主线建议用开源模型。

## 方向二：学生容量下限预测（新方向，独立经济价值）

### 2.1 问题定义
> 给定一个蒸馏任务（教师 + 数据集 + 目标正确率 X%），**在训练前**预测：能达到 X% 的**最小学生模型**是哪个（参数量下限）？

经济价值直接：小学生 = 省显存、省推理成本、省部署费。能预测下限 = 不用把每个尺寸都训一遍试错。

### 2.2 为什么有价值 + 为什么难
- **价值**：部署方最关心"我最少用多大模型能达标"。这是真金白银的成本问题。
- **难点（诚实）**：
  1. 学生能达到的正确率取决于"任务难度 × 学生容量 × 教师质量"三者，关系复杂。
  2. 现有"神经网络缩放定律(scaling laws)"研究的是预训练 loss vs 参数量，**不是蒸馏后下游正确率 vs 学生容量**——这是缺口，也是潜在新意。
  3. 要预测下限，需要一条"学生容量→蒸馏后正确率"的曲线，本身就需要训练多个尺寸学生来拟合（先有数据才能预测）。

### 2.3 和已有工作的区别（prior-art 必查）
| 已有 | 做什么 | 你的差异 |
|---|---|---|
| Scaling laws (Kaplan, Hoffmann/Chinchilla) | 预训练 loss vs 模型/数据规模 | 你预测**蒸馏后下游正确率** vs 学生容量 |
| Distillation scaling law (近期有少量) | 蒸馏的 loss scaling | 你聚焦**MCQ正确率的容量下限 + 任务/难度感知** |
| 模型压缩/选型 | 经验试错 | 你要 training-free 或低成本**预测**下限 |

→ 需 litsearch 第三轮确认"蒸馏后正确率的容量下限预测"是否已被做透。近期已有 distillation scaling law 工作，要小心撞车。

### 2.4 可行的实验设计
1. **建容量-正确率曲线**：固定教师(如 Qwen32B)+数据集(CMExam)，蒸馏**多个尺寸学生**（如 0.5B/1.5B/3B/7B/14B，Qwen2.5 全系列都有）。
   - 本地已有 7B/14B；需补 0.5B/1.5B/3B（小模型下载快、训练快、便宜）。
2. **拟合曲线**：正确率 vs log(参数量)，看是否平滑可外推/内插。
3. **预测下限**：给定目标 X%，从曲线反查最小容量。
4. **难度感知版（结合体检工具）**：用体检的"任务不可信度/难度分布"做特征，预测"该任务的容量下限"——这是和纯 scaling law 的差异点，把体检工具接进来。

### 2.5 与体检工具的协同（潜在亮点）
- 体检工具能量化"任务有多难/教师有多少不可信区"。
- 假设 H6：**任务越难（不可信样本越多），达到目标正确率所需的学生容量下限越高。**
- 若成立 → 体检工具不仅诊断教师，还能**预测学生容量需求** → 工具价值再升级（诊断 + 选型）。

### 2.6 诚实风险
- 容量-正确率曲线可能因任务/教师而异，**外推到没训过的尺寸不可靠**（只能内插）。
- "下限"依赖目标正确率定义，需明确"在哪个测试集、什么阈值"。
- distillation scaling law 是活跃方向，新意需靠"MCQ正确率 + 难度感知 + 体检工具结合"做差异。

## 3. 优先级建议

| 方向 | 成本 | 价值 | 建议 |
|---|---|---|---|
| 融合复活：扩国外模型重算上界 | 低（Llama70B已有，重算上界纯CPU） | 中高 | **先做上界估算**，便宜，直接判断融合是否复活 |
| 学生容量下限：建曲线 | 中（需训多个小学生，但小模型快） | 高（经济价值） | 值得做，先小尺寸快速试 |
| 两者结合：难度感知的容量预测 | 中 | 高（工具升级） | 若上面两步成立，这是最有亮点的合成 |

### 立即可做（不抢GPU，纯CPU）
1. 把 **Llama-3.3-70B**（本地已有）的 logprobs 纳入 fusion_upper_bound 重算（需先生成它的 CMExam logprobs，这步要GPU，排队）。
2. **英文数据集上的 fusion 上界**：用已有的 Qwen32B/Phi4/Yi34B 英文 logprobs（E2已生成）直接算 MedQA/MMLU 上的领域路由上界——**这个现在纯CPU就能做**，立刻验证"英文上是否互补"。

## 4. 一句话

- 方向一：我撤回"全能强者"的过早结论——它是中文局部现象，英文+国外模型很可能让融合复活，**先用现成英文 logprobs 算上界即可初判**。
- 方向二：学生容量下限预测是个有独立经济价值的新问题，且能和体检工具协同（难度→容量需求），但要小心 distillation scaling law 的 prior-art。
