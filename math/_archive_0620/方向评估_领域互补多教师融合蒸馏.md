# 方向评估：用体检工具做"领域互补的多教师融合蒸馏"

> 日期：2026-06-20
> 用户设想：用体检工具找出每个模型各自的"优势领域"，取各模型优势的并集，蒸馏出一个在医学各分支都强的学生模型；
> 再验证该学生在医学各分支的正确率都强。用户判断："那价值更大。"
> 本文：评估价值、可行性、必须正视的 prior-art 风险、以及一个关键诚实警告。

---

## 0. 一句话结论

**这是目前最有"产品级价值"的想法——从"诊断工具"升级到"用诊断结果合成一个更强的模型"。逻辑自洽，且你的实验B已埋好前提证据（教师确实领域互补）。
但它撞上一个成熟领域（多教师蒸馏/教师路由），必须靠"training-free 体检 + 人类难度验证来决定谁教哪个领域"这个独特角度做出差异。
最大风险不是想法不好，而是一个诚实警告：领域级"取并集"在 MCQ 任务上可能增益有限（见第4节），需先用便宜实验验证再投入。**

---

## 1. 想法的内在逻辑（为什么自洽）

1. 实验B 已证明：**不同教师领域强弱不同且互补**——
   - Qwen32B：中医学+4.0、临床+2.4，但口腔−3.9；
   - GLM32B：中西医+4.5，但口腔−7.6；
   - 各教师的"弱区"不完全重叠。
2. 若能"每个领域选当前最可信的教师来教学生" → 学生理论上能集各家之长。
3. 体检工具正好提供"哪个教师在哪个领域可信"的依据（training-free，不需先训练）。

这就是"领域感知的多教师融合蒸馏"：用体检结果做**教师→领域的路由**，而非用单一教师。

---

## 2. 必须正视的 Prior-Art（这个领域很拥挤）

这个想法落在一个成熟方向，审稿人/导师必问"你和它们的区别"：

| 已有方向 | 它们怎么做 | 你的差异（待坐实） |
|---|---|---|
| Multi-teacher KD | 多教师软标签平均/加权蒸馏 | 你按**领域**路由，不是全局平均 |
| Mixture of teachers / teacher routing | 训练门控网络决定用哪个教师 | 你的路由是 **training-free 体检**决定的，不需训练门控 |
| Knowledge fusion / model merging | 合并模型权重 | 你在**数据/标签层**融合，不动权重 |
| MoE 蒸馏 | 专家混合 | 你是"领域→教师"硬路由，更简单可解释 |

**你的潜在独特点（必须验证才能宣称）**：
> "用 training-free 体检 + 外部难度验证，无需训练门控网络，就能为每个领域选出最可信教师，
> 构建领域互补的融合软标签，蒸馏出全领域均强的学生。"

→ 关键差异是 **training-free 路由 + 可解释（领域地图）+ 外部验证（难度）**。
→ 必须做 prior-art 检索（litsearch 第三轮）确认无人完全做过这个组合。

---

## 3. 怎么做（实验设计）

### 3.1 构建"领域路由融合软标签"
- 对每个领域 d，用体检工具选出在 d 上**准确率最高且不可信样本最少**的教师 T_d。
- 学生的训练软标签：每个样本用其所属领域的 T_d 提供的软标签（而非单一教师）。
- 这是 training-free 的：路由由体检（准确率+熵）决定，不训练门控。

### 3.2 对照组（严谨必需）
| 臂 | 说明 | 验证什么 |
|---|---|---|
| 单最强教师（Qwen32B）全程 | 基线 | 融合是否优于"直接用最强的" |
| 简单多教师平均 | 已有方法基线 | 领域路由是否优于平均 |
| **领域路由融合（本方法）** | 每领域选最优教师 | 主结果 |
| 随机路由 | 对照 | 增益是否来自"智能路由"而非"多样性" |

### 3.3 验证学生（用户要的"各分支都强"）
- 在测试集**按学科分组**报告学生准确率，看融合学生是否在各分支都 ≥ 单教师学生。
- 这正是用户要的"验证学生在医学各分支正确率都强"。

---

## 4. 关键诚实警告（投入前必须知道）

**领域路由融合在 MCQ 任务上，增益可能有限。原因：**
1. **强教师本来就覆盖大部分领域**：Qwen32B 整体89%，只有口腔等少数领域弱。融合能改善的只是那几个弱区占的小比例样本 → 整体提升可能只有零点几个百分点。
2. **我们已知的天花板效应**：强教师学生 baseline 已很高（87%+），可提升空间小（这正是 H1 负相关的发现）。
3. **领域路由的收益 ≈ "把少数弱区样本换成更强教师"的收益**，量级可能不大。

→ **所以必须先做一个便宜的"增益上界估算"**，再决定要不要投入完整训练（见第5节）。
→ 若上界就很小，诚实结论是"领域互补存在但融合增益有限"，仍可作为论文的一个诚实分析，但不值得当主卖点。

---

## 5. 建议执行顺序（先便宜验证，再投入）

1. **【最便宜，先做】增益上界估算**（纯分析，无需训练）：
   - 对每个样本，取"所有教师中在该领域最可信的那个"的软标签，算这套"oracle 融合软标签"的**教师准确率**。
   - 对比单一最强教师的准确率。若融合后教师准确率只比最强教师高零点几个点 → 学生增益上界也就那么大 → 谨慎投入。
   - 若融合后教师准确率明显更高（如 89%→93%）→ 值得做完整蒸馏。
2. **【若上界可观】** 做 3.2 的四臂蒸馏（3-seed）+ 3.3 的分学科验证。
3. **【prior-art】** litsearch 第三轮：training-free teacher routing / domain-aware multi-teacher distillation。
4. 据结果决定：主卖点（增益大）还是诚实分析（增益有限但互补存在）。

---

## 6. 价值判断（回答"价值更大吗"）

- **若增益上界可观 + prior-art 有差异**：是的，价值显著更大——从"诊断工具"变成"用诊断造更强模型"，有完整的方法+实用+产品叙事，能冲更好的场。
- **若增益有限**：仍是一个诚实的、有领域地图支撑的分析，但不足以当主卖点；体检工具本身仍是核心贡献。
- **决定性的一步**：第5节的"增益上界估算"——它几乎零成本，却直接告诉你这条路值不值得走。强烈建议先做它。

---

## 7. 与当前进度衔接

- 增益上界估算是纯 CPU 分析，**现在就能做**（用已有6教师 logprobs + 学科标签），不抢 GPU。
- 它复用实验B的领域地图逻辑 + 各教师 logprobs，几十行脚本即可。
- 建议：等用户确认后，先跑增益上界估算，用真实数字判断这条路的天花板，再决定是否投入完整融合蒸馏。
