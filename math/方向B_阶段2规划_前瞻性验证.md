# 方向 B 阶段 2 规划：可蒸馏性几何预测的「前瞻性验证」

> 日期：2026-06-18（待批准后实施，当前 seed8/11 训练完成后再开始）
> 目标：把阶段 1 的回顾性结论升级为**前瞻性预测**——选没碰过的主流大模型，先用几何**预测**其可蒸馏性，再用真实蒸馏**验证**预测是否成立。

---

## 0. 为什么这一步是研究价值的关键跃迁

阶段 1 是「先看到结果，再用几何解释」（retrospective）。这有 p-hacking 嫌疑——任何信号都能事后讲故事。
阶段 2 改成「先用几何预测、锁死结论，再跑蒸馏检验」（prospective）。这是实验科学里最强的证据形式：
**预测在前，验证在后，预测全程不接触学生训练结果。** 如果几何预测的可蒸馏性排序与真实蒸馏增益排序一致，结论就从「相关」上升到「可预测」。

---

## 1. 核心实验设计：预注册 + 盲验证

分三步，严格按顺序，中间设一道「冻结线」防止数据窥探：

**步骤 A — 几何预测（不训练学生）**
1. 选 N 个新教师模型，各自生成 CMExam 训练集真实 logprobs。
2. 用阶段 1 的几何特征 + 已标定的预测器，对每个教师算两个量：
   - 教师级「可蒸馏性分数」（分布尖锐度 / 几何可分性的聚合指标）
   - 几何预测的「样本可蒸馏性 AUC」（该教师的对错在几何上多可分）
3. **预注册**：在跑任何学生训练前，把 N 个教师按「预测蒸馏增益」排序，写进一个带时间戳的 `predictions.json` 并 git 提交。这一步锁死结论。

**冻结线** ←（此后才允许碰学生训练）

**步骤 B — 真实蒸馏验证**
4. 对每个教师，用统一配置蒸馏 Qwen2.5-14B 学生（沿用阶段 1 的 Stage-1-only、seed 三选、991 题测试）。
5. 得到每个教师的真实蒸馏增益（vs 零样本基线）。

**步骤 C — 判定**
6. 计算「预测排序」与「真实增益排序」的 Spearman / Kendall τ。
7. 判据（预注册）：
   - τ ≥ 0.6 且方向正确 → 几何可前瞻性预测可蒸馏性，**结论成立**。
   - 0.3 ≤ τ < 0.6 → 部分成立，几何是有用但不充分的先验。
   - τ < 0.3 → 结论不成立或仅限同族教师，需重新界定边界（这本身也是有价值的负结果）。
8. 加做阶段 1 的算法验证：对每个教师跑 geom_top50 vs baseline，看「几何过滤增益」是否在新模型上复现。

## 3. 资源与工作量估算

| 阶段 | 任务 | 算力 | 时长（4 教师） |
|---|---|---|---|
| 下载模型 | HF/modelscope 下载 4 个模型 | 网络 + ~200GB 磁盘 | 视网速，1-3h |
| 步骤 A | 生成真实 logprobs（4608 样本/模型，单前向） | GPU 串行 | 每模型约 5-15 min，共 ~1h |
| 步骤 A | 几何分析 + 预注册 | CPU | 分钟级 |
| 步骤 B | 蒸馏 14B 学生（每教师 1-3 seed，Stage-1） | GPU 串行 | 每教师每 seed ~16min；4 教师 ×1 seed ≈ 1h，×3 seed ≈ 3h |
| 步骤 C | 排序相关 + 报告 | CPU | 分钟级 |

磁盘：当前剩 391GB。4 个模型（含一个 34B）约需 150-200GB，够用；若选 72B 需先清理或用 AWQ。
单 H100：生成与训练不能并行（OOM），全程串行排队。

**总计**：下载就绪后，纯计算约半天到一天（取决于 1 seed 还是 3 seed 验证）。

## 4. 风险与对策

1. **教师无法稳定输出单字母 / 选项 token 映射歧义**（不同 tokenizer 对 "A" 的编码不同）。
   对策：复用 `get_option_token_ids` 的多候选编码逻辑；每个新模型先在 10 题上验证 token 映射，再全量跑。
2. **N=4 样本太小，排序相关统计力弱**。
   对策：(a) 把已做的 Qwen14B/32B/Llama70B 三个教师纳入同一排序，N 扩到 7；(b) 同时报样本级 AUC（每教师 4608 样本，统计力强），不只依赖教师级排序。
3. **预测与验证间的数据窥探**。对策：predictions.json 先 git 提交并打时间戳，再开训练；报告里明确「预测在前」。
4. **下载受限 / 模型过大**。对策：候选档有冗余，按实际可下载情况替换；优先 AWQ 量化版省磁盘和显存。
5. **弱教师蒸馏可能崩溃（如 CoT 模型 Qwen3 的前车之鉴）**。对策：教师只取选项 logprobs、学生用直答型 Qwen2.5-14B，规避架构-任务错配。

## 7. 预备进展（2026-06-18，下载/训练并行期间完成）

**先验预测器已就绪并验证**：`research/distillability/teacher_distillability_score.py`
给定教师真实 logprobs，输出先验的 `distillability_index`（DI = z(教师准确率) +
z(几何AUC) + z(对错几何可分度)），全程不碰学生蒸馏结果。在已有 3 教师上跑通：

| 排序 | 教师 | acc% | geom_auc | logdet_g | 对错可分度 | DI |
|---|---|---|---|---|---|---|
| 1 | Qwen32B | 89.43 | 0.869 | 21.49 | 1.98 | +2.49 |
| 2 | Qwen14B | 86.00 | 0.856 | 21.42 | 1.70 | +1.72 |
| 3 | Llama70B | 51.64 | 0.663 | 6.05 | 0.48 | −4.21 |

**诚实 caveat（必须写进最终结论）**：这 3 个点只验证预测器「能算、数值自洽」，
不能当作结论已成立。原因：Llama70B→14B 实际蒸出 87.25%（接近 Qwen 教师），说明
「最终学生绝对分数」与 DI 排序并不单调一致。因此阶段 2 的判据必须用**蒸馏增益
(vs 零样本基线)** 而非绝对分数，且要靠 4 个新教师把 DI 的方差拉开，N=7 才有统计意义。
这个 caveat 本身也提示：DI 可能更擅长预测「弱教师该被淘汰」而非「强教师间的细排序」——
阶段 2 应分开报告这两种预测力。

**步骤 A 的工具链已齐**：`teacher_distillability_score.py`（教师级 DI）+
`sample_geometry.py` / `combined_predictor.py`（样本级 AUC）。模型一下载完即可对
4 个新教师生成 logprobs → 直接算 DI → 写入 `predictions.json` 并 git 提交（冻结线）。
